# 踩坑清单

都是实测踩过的，按「症状 → 真实原因 → 做法」写。看到相似症状先查这里，别急着重写脚本。

## 1. 命令一直不返回，不报错也不超时

**症状**：`evalp` / `eval` 跑了十几分钟没输出；连 `(async()=>{await new Promise(r=>setTimeout(r,200)); return 'ok'})()`
这种最小用例也挂死，但纯同步表达式（`"hello"`）秒回。

**原因**：Edge 窗口被别的窗口遮挡 → Chromium 判定页面不可见 → 渲染进程被冻结 →
`setTimeout` 不再触发、Promise 不再推进。同步求值走的是主线程已就绪的调用，所以不受影响，
于是只有"带异步"的调用挂死，非常容易误判成网络问题。

**做法**：任何异步操作前先唤醒：

```powershell
node scripts/cdp.mjs wake <targetId>
```

会发 `Page.bringToFront` + `Emulation.setFocusEmulationEnabled` + `Page.setWebLifecycleState:active`。
`evalp` 自己也会兜底发一次，但批量跑之前显式 wake 更保险。
`capture-xhr.mjs` 在抓包窗口期内每 500ms 唤醒一次，否则页面自己都不会发请求。

## 2. 全局超时时间必须用 JS 层的 race

即使页面醒着，接口也可能不返回。给每个请求包一层 `Promise.race`（见 `talent-query.js` 的 `withTimeout`），
否则一个卡住的请求会把整批拖死。`AbortController` 对已经被反爬 SDK 接管的 `fetch` 无效。

## 3. `fetch` 会挂，`XHR` 不会

在页面上下文里用 `fetch` 调站内接口，可能永远 pending；换成 `XMLHttpRequest` 就正常。
站内 SDK 会给 XHR 补签名，裸 `fetch` 拿不到那套处理。**所有接口调用都用 XHR。**

## 4. 接口不需要签名头，但需要 cookie

抓到的真实请求头里没有 `X-Bogus` / `a_bogus` / `msToken`，只有 cookie 加 `x-mt-fe-platform` 之类的业务头。
所以**不要自己拼 HTTP 请求去调**（cookie + 页面同源上下文缺一不可），一律在页面内发起。

## 5. `filter_item_params` 的 schema

值是数组的 map：`{"CooperationStatus":["Cooperated"]}`。写成字符串、写成数组 of object 都会报
`JSON-TO-THRIFT dismatched types`。这个 schema 猜不出来，是靠抓 UI 的真实请求确定的。

## 6. 搜索框不是 `input`

广场顶部那个「搜索达人昵称/抖音号」占位符实际是个 `byted-popper-trigger-click`，
里面没有 `input`；点开后才在浮层里渲染出真正的输入框。

**由此产生的坑**：这次搜索开的浮层不会自动关，会静静盖住下面 ~250px 的区域，
随后所有按坐标点击都会打在浮层/浮层后面的元素上。表现是 `elementFromPoint` 命中的东西
和你要点的东西完全无关。做法是先 `key Escape` 关掉浮层再点。
`act.mjs` 的 `click` / `clickxy` 都会回报 `hit=...`，命中明显不对时先查浮层。

## 7. 详情页的横向布局

详情页「带货品类」这个选择器在布局最右侧，视口宽度不够时会被裁到屏幕外，
此时拿到的 `getBoundingClientRect().x` 大于 `window.innerWidth`，按坐标点是无效的。
先 `scrollIntoView({inline:'center'})` 再取坐标。

## 8. 搜索是模糊匹配，且不是子串匹配

- `大发` → 命中 `暴暴大发现`（`大发` 是它中间两个字）、`大润发（三水店）`
- `赵赵` → 命中 `赵赵.（MCN松柏文化）`、`赵赵厨房`、`爱唱歌赵先生（赵封鹏）`

所以**不能**用"名字里包含这两个字"当匹配规则。用「全等 > 前缀 > 包含」+ 常驻城市 +
**订单地域第一位**。订单地域那条最可靠：本地商家对应的达人，下单用户第一位必然是本市。

## 9. emoji / 变体字符昵称

`酷7` 全站搜不到，实际昵称是 `酷7⃣️`（`7` + U+FE0F + U+20E3）。
关键词搜索对这类字符匹配不上，「酷7」「酷七」「酷⑦」「酷7⃣️」全试过都是 0 结果。

**兜底**：拉城市达人池（`op:"cityPool"`，`provinceCity` 过滤）分页扫，本地正则匹配。
另一条线索是同机构达人简介里的 @提及 —— 这次就是从小七探齐齐的简介
「终身合作伙伴：@酷7⃣️」拿到的准确写法。

## 10. 昵称里的空格

`三 岁 呀 ³` 每个字之间有空格。做匹配和回写时都要注意，别把带空格的昵称和名单里的写法当成两个人。

## 11. 平台不给的字段要留空，不要填 0

某品类不在 top5 时不带 `category` 的接口拿不到它；带上 `category` 后如果该品类没有成交，
平台返回 `<100` 或空。这两种情况都不等于 0，填 0 会造出一个假结论。

## 12. 该连哪个实例：复用 9222 上已有那个，别再起一个

正解是**复用**已经在 9222 上监听的那个实例。它通常就是用户为这次任务开好的、
**带着真实登录态**的实例 —— 另起一个 profile 会同时踩两个坑：9222 端口冲突，
而且新 profile 是干净的、没有登录 cookie，等于逼用户重新扫码。

判断标准是「它答不答 9222」，**不是**「`--user-data-dir` 是不是我建的」。要避开的是
**用户日常那个浏览器窗口** —— 它压根没开调试端口，你连不上它。

复用时的纪律：只 `Target.createTarget` 开自己的标签页，不要导航、不要关闭用户已经开着的页面。
`cdp.mjs list` 里同一站点会有多个 page target（广场 / 详情 / 首页 / 新标签页），挂哪个都行，
但所有调用都落在自己的 tab 上。

副作用提醒：复用意味着**可能有第三方并发操作同一个实例**（实测遇到过广场页 target
在批量途中被换掉、又冒出几个新 target）。所以长批量开始前重新跑一次 `whoami` + `wake`。

## 13. Windows 上跑这些脚本

- `python3` 不存在，用 `python` / `py`
- 给 `evalp` 传 JSON 优先写 `.json` 文件传路径；PowerShell 会吃掉内联 JSON 里的引号
- 中文内容的脚本用 pwsh 7+ 跑；PowerShell 5.1 按 GBK 读文件会乱码

## 14. 品类填错是「假成功」，不是报错

`category` 填平台不认识的品类名（比如把用户表头列名「小吃快餐」直接当参数，平台要的是「快餐小吃」）时，
接口返回 **HTTP 200**，但响应里**没有 `talent_item_gmv`**。不报错、不抛异常、不 4xx ——
唯一痕迹是 `categoryErr: 200`。

**症状**：品类那一列批量跑完全空，日志里却没有任何错误。很容易误判成网络/登录问题，
然后去重跑、重连、重开页面，全是白费。

**做法**：先不带 `category` 请求一次同一接口，从 `talent_great_category_data.category_name[]`
读出平台真实品类名；或用 `search/config/?from_type=5` 里 `filter_items[].key=cateTag` 的候选值。
**别拿用户列名直接当参数，也别试「小吃」「快餐」「美食」这类自造简称。**

**推论（更一般）**：这类站内接口用「200 + 静默缺字段」表达参数不被接受。
字段批量取空但无错误时，先怀疑**参数名/口径**，再怀疑链路。

## 15. 「top5 里没这个品类」≠「这个达人没这个品类」

`talent_great_category_data` **只给 top5**。实测 `大发` 的 top5 是
汽车服务 / 休闲食品 / 地方菜 / 景点票券 / 传统娱乐 —— 里面**没有**「快餐小吃」，
但带 `category=快餐小吃` 请求，平台直出 **0.36w**；`酷7` 同理，直出 `<0.01w`。
三个人其实都有该品类成交，其中两个不在 top5 里。

**症状**：品类列被填成「无」「—」「0」，或者只有少数几个人有值。
这是**假阴性** —— 比假成功更隐蔽，因为结果看起来「有结论」。

**做法**：这一列的权威来源只有一个 —— 带 `category` 参数单独请求 `detail/indicator`。
top5 那张卡只能用来**发现平台品类名**，不能用来**判断有没有成交**。
`<100` 表示确有成交但不足百元，写 `<0.01w`；**不要写 0，也不要写「无」**。
